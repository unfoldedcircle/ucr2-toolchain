# Remote Two/3 toolchain

Build toolchains for the [Unfolded Circle](https://www.unfoldedcircle.com/) Remote Two and Remote 3 remote controls,
and for the desktop simulator of their user interface.

The repository contains two things:

1. A [Buildroot](https://buildroot.org/) external tree that produces the cross-compilation SDK for the devices: the
   aarch64 compiler and a sysroot with the same libraries as the device firmware. It is not the embedded Linux
   system running on the device, only what is needed to compile against it.
2. Docker images with a statically built Qt 5.15 for building
   the [remote-ui](https://github.com/unfoldedcircle/remote-ui)
   application: one that cross-compiles it for the devices, and two for the desktop simulator on Linux and Windows.

If you want to build a custom remote-ui for your device or try the simulator on a desktop, the Docker images are all
you need. Building the SDK yourself is only required when the sysroot has to change.

## Repository layout

| Path                   | Content                                                                                                    |
|------------------------|------------------------------------------------------------------------------------------------------------|
| `buildroot/`           | Buildroot, as a git submodule (2023.02.1)                                                                  |
| `buildroot-external/`  | Buildroot external tree: board configuration, packages, patches and scripts                                |
| `build.sh`, `Makefile` | Build wrappers for the Buildroot targets                                                                   |
| `docker/`              | Docker image: device cross-compile toolchain with static Qt                                                |
| `docker-linux-x64/`    | Docker image: static Qt for the Linux x64 desktop simulator                                                |
| `docker-windows-x64/`  | Docker image: MXE (mingw-w64) cross-compile toolchain with static Qt for the Windows x64 desktop simulator |
| `licenses/`            | License texts and manifest of the packages in the SDK, generated by `legal-info.sh`                        |
| `CHANGELOG.md`         | Notable changes per release                                                                                |

## Docker images

All images work the same way: bind-mount a remote-ui checkout to `/sources`, run the container, and the binary
appears in the checkout under `binaries/`. The container runs `qmake CONFIG+=static CONFIG+=release` and `make`
with the user and group id of the host, so the build output has the same ownership as the sources. Each image
README documents the build of the image itself, its Qt configuration and the runtime requirements of the result.

| Image                                                              | Builds                                                                                            | Output                                       | Documentation                                                |
|--------------------------------------------------------------------|---------------------------------------------------------------------------------------------------|----------------------------------------------|--------------------------------------------------------------|
| `unfoldedcircle/r2-toolchain-qt-5.15.19-static`                    | remote-ui for Remote Two/3 (aarch64, static Qt on the Buildroot sysroot)                          | `binaries/linux-arm64/release/remote-ui`     | [docker/README.md](docker/README.md)                         |
| `unfoldedcircle/remote-ui-toolchain-qt-5.15.19-static-x64`         | Linux x64 desktop simulator, runs on Ubuntu 24.04 / Debian 13 and newer without a Qt installation | `binaries/linux-x64/release/remote-ui`       | [docker-linux-x64/README.md](docker-linux-x64/README.md)     |
| `unfoldedcircle/remote-ui-toolchain-qt-5.15.19-static-windows-x64` | Windows x64 desktop simulator, cross-compiled on Linux (experimental)                             | `binaries/windows-x64/release/remote-ui.exe` | [docker-windows-x64/README.md](docker-windows-x64/README.md) |

The images are published on [Docker Hub](https://hub.docker.com/u/unfoldedcircle). Every image is tagged with its
version and with `latest`; the image name carries the Qt version.

Cross-compiling remote-ui for the device, for example:

```shell
docker run --rm -it \
  --user=$(id -u):$(id -g) \
  -v ~/projects/remote-ui:/sources \
  unfoldedcircle/r2-toolchain-qt-5.15.19-static
```

The remote-ui repository wraps these calls in `make` targets (`make ucr2`, `make linux-x64`, `make windows-x64`) and
describes installing a custom build on the device in its
[cross-compile documentation](https://github.com/unfoldedcircle/remote-ui/blob/main/docs/cross-compile.md) and the
desktop builds in [static-compile.md](https://github.com/unfoldedcircle/remote-ui/blob/main/docs/static-compile.md).

Why static Qt: the device firmware ships no Qt libraries, the application has to bring its own. Buildroot dropped
support for static Qt 5 builds, so the images compile Qt from the
[qt-everywhere source archives](https://download.qt.io/archive/qt/5.15/) against the SDK sysroot instead. The desktop
images follow the same approach so that a simulator binary can be tried without installing Qt.

## Buildroot SDK

The SDK is a relocatable Buildroot toolchain archive for `aarch64-buildroot-linux-gnu`, built for the Cortex-A55 of
the devices with the Arm GNU Toolchain 10.3 as external compiler. Its sysroot contains the libraries of the device
firmware (see `licenses/` for the full list) so that an application built against it runs on the device.
The SDK contains no Qt; the Docker image in `docker/` adds it.

SDK archives are attached to the [GitHub releases](https://github.com/unfoldedcircle/ucr2-toolchain/releases) as
`ucr2-aarch64-toolchain-<version>-noqt.tar.gz`, and the device image downloads the archive of the version set in
`docker/build.sh`. Consumers therefore need neither Buildroot nor this repository.

### Building the SDK

Building requires a Linux host with the
[Buildroot system requirements](https://buildroot.org/downloads/manual/manual.html#requirement), around 20 GB of disk
space and, depending on the machine, one to a few hours for the first build.

```shell
git clone --recurse-submodules https://github.com/unfoldedcircle/ucr2-toolchain.git
cd ucr2-toolchain
./build.sh ucr2_toolchain-sdk
```

The archive is written to `release/ucr2-aarch64-toolchain-<version>-noqt.tar.gz`, where the version comes from the
git tag. `make help` lists the other targets: `ucr2_toolchain-config` and `ucr2_toolchain-menuconfig` to initialise or
change the configuration (`make ucr2_toolchain-menuconfig` also writes the changes back to the defconfig),
`ucr2_toolchain-legal-info` to collect the license information, `clean` to remove the build output. The Buildroot
manual explains
the [cross-compilation toolchain](https://buildroot.org/downloads/manual/manual.html#_cross_compilation_toolchain)
and the [external tree mechanism](https://buildroot.org/downloads/manual/manual.html#outside-br-custom) used here.

`legal-info.sh` runs the legal-info target and copies the resulting license texts and manifest into `licenses/`; it
is run for every SDK release.

## Releases

Version tags (`v<major>.<minor>.<patch>`) on `main` create a GitHub release, every other push to `main` updates the
`latest` pre-release. The SDK archive is built with `build.sh` (the build takes hours and is not part of the
workflow) and attached to the release by hand. The changelog lists what changed per version. The version of the SDK is
independent of the Qt version: the Docker images name the Qt version in the image name and carry the SDK or image
version as tag.

The sysroot must stay in sync with the device firmware. An SDK built from a different firmware generation can
produce binaries that link against libraries the device does not have, which is why the 0.6.0 pre-release is
deprecated in favour of the 1.0.x releases.
